Draft a ticket for the work we discussed. Do not publish it yet.

## Ticket content

- Give it a short, specific title.
- Describe the problem and the desired outcome.
- Prefer bullet points for distinct requirements.
- Include only requirements and constraints we have agreed on.
- Follow the repository's issue template if one exists, without inventing content for its sections.
- Keep it as short as the work allows. Do not add sections just to fill a template.

## Restrictions

This is a ticket, not an implementation plan.

Do not include:
- Implementation steps, file lists, functions, or proposed internal architecture.
- Test plans, validation commands, coverage targets, or verification reports.
- Agent workflow, review procedures, commits, or PR instructions.
- Speculative risks, rollout plans, fallback behavior, compatibility, or unrelated cleanup.
- Requirements inferred from your own preferences.

Acceptance criteria, when useful, must describe observable outcomes—not implementation or testing instructions.

Include technical details only when necessary to explain the problem or record an explicitly agreed constraint.

1. Proposed ticket title and body.
2. Questions that genuinely block the draft, if any, outside the ticket body.
