## Host facts this plan depends on

| Fact | Value | How it was established |
|---|---|---|
| Architecture | **Intel `x86_64`** | `uname -m`, `sysctl machdep.cpu.brand_string` → Core i9-9880H |
| Homebrew prefix | **`/usr/local`** | `brew --prefix`; `which brew` → `/usr/local/bin/brew` |
| `/opt/homebrew` | **does not exist** | `ls -1d /opt/homebrew` |
| autossh binary | `/usr/local/bin/autossh` | `which autossh` |

**This is not an Apple Silicon machine.** Every backend and binary asset named below was verified for
`x86_64` / `osx-64` / `macOS_amd64`, not `arm64`.

### Consequence: the `/opt/homebrew` paths in the repo are already broken

`zsh/.zsh_script:105` guards on `[[ ! -x /opt/homebrew/bin/autossh ]]`. On this host that test always
succeeds, so `vm-tab` bails with "`/opt/homebrew/bin/autossh is required`" and never runs. The 14
`/opt/homebrew/bin/autossh` commands in `ghostty/workspaces/*.toml` fail the same way.

These are **pre-existing bugs, not regressions this plan introduces.** They are also why "strip the
hardcoded Homebrew paths" below is a genuine fix rather than pure preparation — and they weaken the
case for keeping either `autossh` or the Ghostty workspaces.

## Context & Goal

Two related pieces of work, ordered so the second is smaller and safer than it would otherwise be:

1. **Trim the repo.** Archive `zwm` and the Ghostty workspaces; delete `television`, `hunk`, and `bin/lc`.
2. **Retire the Brewfile entirely.** Its remaining 20 formulae move to mise, so tool versions are
   pinned and identical on this Mac and `vm-us`.

### What the investigation established

- **16 of the 26 formulae come from mise's own registry.** 4 more install through explicit
  `aqua:` / `ubi:` / `github:` / `conda:` backends. 6 are being dropped. That accounts for all 26,
  so `Brewfile` is **deleted outright**, not shrunk.
- **`autossh` is not installable by any mise backend.** Absent from mise's registry, the aqua
  registry, and conda-forge; upstream publishes no binaries (only `autossh-1.4g.tgz`, 2013).
- **Homebrew stays installed regardless.** It manages ~40 formulae outside this Brewfile plus 8
  casks (`ghostty`, `utm`, `bitwarden`, `alt-tab`, `macfuse`, `tunnelblick`, two fonts). The Brewfile
  is a curated subset, so there is no dual-bootstrap cost — only the cost of the curated set living in
  a second place. Mise itself will be installed via Homebrew.
- **The trim removes most of the tool-removal work.** `autossh` has 16 command sites, 14 of them in
  `ghostty/workspaces/*.toml`; archiving those files deletes those sites for free. `mcat`'s only
  consumer is `television/cable/screenshots.toml`, which stops existing in Phase 0.

## Tidy, First

Three kinds of change are deliberately separated, because combining them makes every failure
ambiguous:

1. **Phase 0 removes and relocates whole capabilities.** No installer changes. Afterwards the repo is
   smaller, still fully Homebrew-backed, and verified working.
2. **Phase 1 removes six tools and their remaining config sites**, still with no installer change.
3. **Phase 2 swaps the installer over a fixed, smaller tool set.**

A broken `visible_files` is otherwise indistinguishable from a missing mise shim. Sequencing makes
every failure attributable to exactly one cause.

Phase 2 additionally strips the hardcoded `/opt/homebrew/bin/` prefixes **before** mise arrives, so
the backend swap changes nothing at any call site — and fixes the pre-existing breakage described
above as a side effect.

### 2c. Bootstrap: how mise itself gets installed

There is a chicken-and-egg: `mise install` needs `mise`, and `mise` is absent from this host. The
existing `brew:` recipe already solves the same problem for Homebrew (justfile:17-20 installs it when
missing), so the bootstrap reuses that shape.

```
just mise
  ├─ 1. ensure Homebrew present           reuse justfile:17-26 logic
  ├─ 2. brew install mise                 skip if `mise` is already on PATH
  ├─ 3. symlink mise/config.toml → ~/.config/mise/config.toml
  ├─ 4. mise trust ~/.config/mise/config.toml
  └─ 5. mise install
```

Ordering constraints, each for a concrete reason:

- **3 before 5.** `mise install` reads the global config. Without the symlink it installs nothing.
- **4 before 5.** mise refuses to act on an untrusted config. A *symlinked* global config is the case
  where trust is not implicit — this needs verifying on the actual host, since mise may already trust
  `~/.config/mise/config.toml` by path regardless of what it points at.
- **2 via Homebrew, not the standalone installer.** Homebrew stays on both hosts regardless (casks on
  the Mac, ~40 remaining formulae), so this adds no new dependency. `curl https://mise.run | sh` is the
  alternative if Homebrew is ever dropped — a separate decision.

### 2d. PATH propagation — five contexts, only one of them interactive

**Decision: use shims, not `mise activate`.** mise surfaces tools two ways, and they are not equivalent:

- **`mise activate`** installs a shell hook. Interactive shells only.
- **Shims** in `~/.local/share/mise/shims` placed on `PATH`. Works anywhere.

Most of this repo's tool resolution is *not* interactive zsh, so the shims directory is the mechanism.
`mise activate` becomes optional — it would only affect interactive shells.

| Context | Where | Resolves tools today from | Needs |
|---|---|---|---|
| Interactive zsh | `zsh/.zshrc` | `brew shellenv`, `~/.local/bin` | shims dir on `PATH` |
| tmux | `tmux/tmux.conf:97` | explicit `PATH` incl. `/usr/local/bin` | shims dir added to that `set-environment` value |
| launchd services | `bin/lch/lch/launchd.py:30` (`LAUNCHD_PATH`) | explicit `PATH` incl. `/usr/local/bin` | shims dir added |
| Zed terminals | `zed/settings.json:30` snippet | inherits Zed's environment | shims dir reachable — **verify how Zed builds `PATH`** |
| Non-interactive shells | inherited | `PATH` | covered once the shims dir is on `PATH` |

Concrete, verified breakage if this is skipped:

- **`gitmux`** — `tmux/tmux.conf:181` runs it as `#(gitmux -timeout 200ms ...)`. tmux executes `#()`
  jobs through its own shell using the server environment PATH set at `tmux.conf:97`, **not** through
  an interactive zsh, so the status line would lose its branch display.
- **`tmux` itself** — `opener_tunnel/config.toml:21` declares `command = ["tmux"]`, and
  `bin/opener_tunnel/opener_tunnel/supervisor.py` runs it to host the tunnel session. The launchd
  service `lch-opener-tunnel` resolves that bare `tmux` through `LAUNCHD_PATH`, so the browser-opener
  tunnel would fail to start.
- **`tmux` in the Zed snippet** — the replacement `terminal_init_command` also calls bare `tmux`. If Zed
  is launched from Finder it inherits the launchd environment rather than a login shell's `PATH`, so
  `/usr/local/bin` may still be present (system default) while the shims dir is not.
- **Not affected: `jq`.** It is used in `justfile` recipes and `herdr/*.zsh` scripts, all of which run
  from a shell that inherits `PATH`.

## Note: `zed/settings.json` `terminal_init_command`

The value is `eval "$(zwm terminal-init-command-session)"`. It is the only remaining live dependency on
the `zwm` binary besides the launchd service and the `justfile` recipe.

What it actually does (verified in `bin/zwm/application.go:193-228` and
`bin/zwm/internal/inventory/record.go:36-61`):

1. Resolves the Git worktree root via `git rev-parse --show-toplevel`.
2. Derives a deterministic tmux session name:
   `zwm-v1-<first 8 hex of sha256(worktree path)>-<parent dir>-<leaf dir>`, e.g.
   `zwm-v1-deadbeef-example-project-wt`. On a hash collision it re-derives with 16 hex characters
   (`bin/zwm/terminal_initializer.go:14-44`).
3. Emits shell code that creates the session if absent, sets `@zwm_worktree`, sets the tab title, and
   `exec`s `tmux attach-session`.

So Zed's integrated terminal auto-attaches to its worktree's durable tmux session. This is real
behaviour, not a stub.

**Decision: replace with a self-contained snippet, not delete.**

Note first that `zwm` is **not currently installed** — neither `~/.local/bin/zwm` nor `~/go/bin/zwm`
exists, and the `lch-zwm` service exits 1. So this setting is already broken on this host, in the same
way the autossh paths are. The replacement restores behaviour rather than merely preserving it.

`NormalizeWorktree` is only `path.Clean` (`record.go:36-42`), which `git rev-parse --show-toplevel`
already returns, so the session name is fully reproducible in shell:

```zsh
root=$(git rev-parse --show-toplevel 2>/dev/null) || exit
session="zed-$(printf %s "$root" | shasum -a 256 | cut -c1-8)-$(basename "$(dirname "$root")")-$(basename "$root")"
tmux has-session -t "$session" 2>/dev/null || tmux new-session -d -s "$session" -c "$root"
printf '\033]2;%s\007' "$(basename "$(dirname "$root")")/$(basename "$root")"
exec tmux attach-session -t "$session"
```

JSON-escaped as a single line, this goes in `zed/settings.json:30`.

Three deliberate properties:

- **Prefix is `zed-`, not `zwm-v1-`.** Verified safe: `zwm-v1` appears only inside `bin/zwm/*`, and
  `tmux list-sessions` shows no live `zwm-v1-*` sessions — only `blog` and `dotfiles`. Nothing is
  orphaned by the rename.
- **The `tmux set-option @zwm_worktree` line is dropped.** Verified: `@zwm_worktree` is read only by
  `bin/zwm/*` (`tmux_client.go:28`, `application.go:223`), which used it to repair metadata after a
  tmux-continuum restore. Archiving `zwm` leaves nothing that reads it.
- **The 16-character hash-collision fallback is dropped.** It existed to disambiguate two worktrees
  whose first 8 hash characters collide. Rare enough to accept.

**Why this is one line in JSON rather than a function in `zsh/.zsh_script`.** The repo already has
precedent for the function approach — `ss()`, `hunk()`, `vm-tab()`, `fz()` all live in `zsh/.zsh_script`,
and `.agents/plans/hunk-zsh-migration.md` did exactly that migration. But a function is only visible if
Zed sources `.zshrc` before running `terminal_init_command`, and that is **unverified**. If verification
shows `.zshrc` *is* sourced, this should be refactored into a `zsh/.zsh_script` function to match the
existing pattern; until then the self-contained form is the one that cannot fail on that ambiguity.

**PATH caveat:** the snippet calls bare `tmux`. Today that resolves from `/usr/local/bin`; after
migration it lives under the mise shims directory, so whatever `PATH` Zed hands its terminals must
include it. See 2d.

## Out of scope

- Casks and the ~40 non-Brewfile formulae (`btop`, `awscli`, `docker`, `just`, `glab`, `consul`,
  `nomad`, `hdf5`, `cmake`, …). Homebrew keeps managing these.
- `tuicr/`, `lazygit/`, `harlequin/`, `lch/`, `macflow/`, `screenshot/`, `opener_tunnel/` — untouched.
- `bin/<tool>/` packages other than `zwm`, `ghostty_workspace`, `hunk-review` and `bin/lc`, which build
  through `uv` or their own `justfile` independently of this change.
- `opencode/` and `ghostty/` configs that reference `/opt/homebrew/**` in sandbox/permission
  allowlists — harmless, and out of scope for a path-prefix cleanup.
